## 무엇이 백엔드로 도는가

```
브라우저 (GitHub Pages)
  ├─→ 로그인          →  Supabase Auth
  ├─→ 이력 저장/조회   →  Supabase DB   (RLS로 내 것만)
  └─→ 카드 해석 요청   →  Supabase Edge Function  →  Claude API
                          (여기에만 ANTHROPIC_API_KEY 가 있다)
```

- **저장** — 해석까지 받은 뒤 `readings` 테이블에 INSERT 한 번. 새로고침·다른 기기에서도 남는다
- **내 것만 조회** — DB의 RLS 정책(`auth.uid() = user_id`)이 거른다. 프론트가 보내는 값을 믿지 않는다
- **AI 해석** — Claude API 키를 브라우저에 두면 페이지 소스로 유출되므로 Edge Function을 거친다

## 보안

- `ANTHROPIC_API_KEY` 는 Edge Function 환경변수(`Deno.env.get`)에만 있다. 프론트 코드·저장소 어디에도 없다
- `readings` 에 RLS ON + 정책 3개(select / insert / delete, 전부 `auth.uid() = user_id`)
- **RLS는 계정 두 개로 양방향 실제 확인했다.** 서로의 기록이 보이지 않는다
  (대시보드 SQL Editor는 소유자 권한이라 RLS를 적용받지 않아 그 창에서는 확인할 수 없다 — [`PRD_tarot.md` 8절](PRD_tarot.md#8-보안))
- `config.js` 의 `SUPABASE_ANON_KEY` 는 공개 키다. 이것만으로는 남의 기록을 볼 수 없다. 막는 것은 RLS다
- Anthropic Console에 월 $10 사용량 한도·알림 설정

## 만들면서 정한 것

- 스프레드 **1장**(오늘의 카드), **정방향만**
- 카드 이름은 **영어로 저장** (`The Fool`, `Ace of Wands` …)
- 저장은 해석까지 받은 뒤 **INSERT 한 번**. UPDATE 없음 — 이유는 [`PRD_tarot.md` 7절](PRD_tarot.md#7-창구-엔드포인트)
- 이메일 확인(Confirm email) **켬**. 대신 확인 전용 페이지와 상황별 한국어 안내를 넣었다
- 카드 그림은 Rider–Waite 덱(1909년 발행, 저작권 만료), 위키미디어 커먼즈

## 회고

### 1. 내 화면이 세상과 끊겨 있던 이유 — 손님·주방 비유로 한 문장

메뉴판과 손님 자리는 다 차려 놨는데 주방이 없어서, 주문을 받아도 아무것도 만들어 나오지 않고 손님이 나가면 주문 기록도 같이 사라지는 가게였다.

카드를 뽑고 그림을 보여주는 것까지는 화면 혼자 할 수 있었다. 하지만 해석을 만들어 줄 곳(주방)이 없었고, 뽑은 것을 적어 둘 곳(장부)도 없었다. 그래서 새로고침하면 방금 뽑은 것이 사라졌다. `localhost:5500` 은 내 컴퓨터를 가리키는 주소라서 남에게 보내도 열리지 않았고, 그것마저 나 혼자 보는 가게였다.

### 2. 404와 500 중 더 만나고 싶지 않은 것과 이유

**500이 더 싫다. 404는 내가 어디를 잘못 짚었는지 알려주는데, 500은 아무것도 알려주지 않기 때문이다.**

이번에 확인 메일 링크가 `http://localhost:3000` 으로 돌아가 아무것도 열리지 않은 일이 있었다. Supabase의 `Site URL` 기본값이 그 주소였고 내 서버는 5500번이었다. 답답했지만 **어디가 틀렸는지는 분명했다** — 주소다. 주소를 고쳐서 끝났다.

500(과 내가 직접 돌려주게 만든 502)은 다르다. 서버 안에서 무언가 터졌다는 것만 알려주고, 무엇이 터졌는지는 브라우저에 나오지 않는다. Edge Function이 Claude 호출에 실패해 502를 돌려줄 때, 원인은 함수 로그를 따로 열어야 보였다. 화면만 보고 있으면 고칠 단서가 없다.

### 3. '먼저 예측' 표에서 틀리게 예측했던 항목

**"정책을 넣었으니 RLS 확인은 끝났다"** 고 예측한 것이 틀렸다.

`readings` 에 RLS를 켜고 정책 3개를 넣은 뒤 확인이 끝난 줄 알았다. 그런데 정책을 **넣은 것**과 정책이 **실제로 걸러내는 것**은 다른 일이었다. 확인하려고 열었던 Supabase 대시보드의 SQL Editor는 프로젝트 소유자 권한으로 붙기 때문에 RLS를 통과하는 게 아니라 아예 적용받지 않았고, 그 창에는 로그인한 사용자가 없어서 `auth.uid()` 가 `null` 이었다. **확인하려고 쓴 도구가 확인이 불가능한 도구였다.**

결국 계정 두 개를 만들어 서로의 기록이 보이지 않는 것을 양방향으로 확인했다.

같은 종류로 틀린 예측이 둘 더 있었다.
- **"고쳤으니 반영됐을 것"** — Edge Function은 고친 뒤 다시 배포해야 바뀐다. 고친 것과 반영된 것은 다르다
- **"저장소에 올렸으니 웹사이트가 될 것"** — GitHub은 기본이 파일 보관소다. `Settings → Pages` 를 켜야 그 파일이 웹사이트로 서비스된다

### 4. AI에게 보안을 맡길 때 반드시 되물어야 할 질문 하나

**"그게 막힌다는 걸 어떻게 확인했나 — 설정이 있다는 것만 봤나, 실제로 막히는 것을 봤나?"**

이번에 내가 그 함정에 그대로 빠졌다. "RLS 확인 완료" 라고 적혀 있었지만 확인된 것은 정책이 존재한다는 것까지였다. 설정을 넣었다는 보고와 그 설정이 작동한다는 확인은 다른 말인데, 문장으로는 똑같이 "완료"로 적힌다.

AI 코딩 도구로 만든 테이블은 RLS가 꺼진 채 시작되는 경우가 많다. 실제로 이 문제로 수백 개 앱의 데이터가 노출된 사고가 있었다(CVE-2025-48757). 막는 장치가 있느냐를 묻는 것으로는 부족하고, **막히는 장면을 봤느냐**를 물어야 한다.

## 로컬에서 실행

```bash
python -m http.server 5500
```

`http://localhost:5500` 을 연다. 빌드 도구 없이 순수 HTML/CSS/JS 이고, Supabase JS는 CDN으로 불러온다.

Supabase의 `Authentication → URL Configuration → Redirect URLs` 에 실행 주소가 등록돼 있어야
가입 확인 링크가 돌아온다.
